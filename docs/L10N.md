# Localization

Redrob's own UI is translatable and ships Korean. Chromium's UI was already translated — it ships `ko.pak` with
440 locales and always has — so before this the window showed a translated address bar above an untranslated
sidebar, which is worse than being English throughout because it looks like a bug rather than a gap.

## One row per string

Everything derives from `l10n/*.tsv`:

```
key <TAB> English <TAB> Korean [<TAB> description]
```

`scripts/gen_strings.py` (or `redrob.py strings`) turns those into three generated files, all of them checked in
and all of them under `sources/` so `apply` copies them into the checkout:

| Generated | What reads it |
|---|---|
| `sources/chrome/browser/redrob/resources/redrob_strings.grd` | grit → `IDS_REDROB_*` header and 84 per-locale `.pak` files |
| `.../translations/redrob_strings_ko.xtb` | grit, keyed by a fingerprint of the English |
| `.../redrob_localized_strings.h` | the three WebUI data sources, as `kRedrobLocalizedStrings` |

The reason for generating rather than hand-writing: a localized string has to exist in three places that must
agree — the English in a `.grd`, the Korean in a `.xtb` keyed by a **hash of the English**, and a compile-time id
or a `$i18n{}` key at the use site. Hand-maintaining that is how a string ends up translated in one place and
English in another. `redrob.py check` fails if any generated file has drifted from the TSV.

The `.xtb` id is `str(FingerPrint(presentable_content) & 0x7FFFFFFFFFFFFFFF)`, reimplemented in
`gen_strings.py` so `check` works with no Chromium checkout, and **cross-checked against grit's own module**
whenever a checkout is present. That cross-check is not decoration: a wrong id fails **silently** — grit drops a
translation it cannot match and falls back to English, so a typo ships an untranslated UI on a green build.

## Adding a string

1. Add a row to the right `l10n/*.tsv`. Reuse an existing key if the English is identical — `gen_strings.py`
   refuses two rows with the same English text, because grit's id is a hash of that text and two rows would be
   one clique with two translations, which trips an assert inside `xtb_reader`.
2. `./scripts/redrob.py strings`
3. Use it:
   - **C++ views**: `l10n_util::GetStringUTF16(IDS_REDROB_SIDEBAR_BOOKMARKS)`. The name is the key in
     `UPPER_SNAKE` with an `IDS_REDROB_` prefix. The target needs
     `//chrome/browser/redrob/resources:redrob_strings` in its `deps`.
   - **WebUI HTML**: `$i18n{sidebarBookmarks}`, or `$i18nRaw{…}` for a string that carries its own markup.
   - **WebUI TypeScript**: `loadTimeData.getString('sidebarBookmarks')`, or `getStringF` with `$1`…`$9`.
4. `./scripts/redrob.py check`

## Two traps that cost a build each

**`$i18n{}` does not work in TypeScript.** `EnableReplaceI18nInJS()` sounds like it makes it work and does not:
`ReplaceTemplateExpressionsInJS` substitutes only inside HTML template literals — Lit's and Polymer's
`` html`…` `` — so in a hand-written `.ts` a `'$i18n{key}'` literal is copied through untouched and the user sees
`$i18n{obContinue}` on a button, on a green build. The path for TypeScript is `UseStringsJs()` on the data source,
`<script type="module" src="strings.m.js"></script>` **before** the page's own module, and
`loadTimeData.getString`. HTML is different and needs none of that: `text/html` gets template replacement for
free, so `AddLocalizedStrings` alone is enough there.

**A sentence split around markup breaks in Korean.** `Tasks the browser starts on its own. A <strong>schedule</strong>
starts …` split into fragments renders the newline between two `$i18n{}` as a space, which English wants and
Korean does not — the particle attaches directly to the noun, and it came out `일정 은` instead of `일정은`. The
fix is one string per sentence carrying its own `<strong>`, emitted with `$i18nRaw{}`. That is not a
sanitization question: the string comes from `l10n/*.tsv`, not from a user. When such a string wraps an element
the TypeScript addresses by id, the `id=` has to stay **inside** the translated markup — `#rpc-handle` is the
example.

## The upstream wiring

Three lines in Chromium, all in `patches/`:

- `tools/gritsettings/resource_ids.spec` — the id range, **13000**, deliberately last in the file and far above
  everything upstream allocates. Both halves of that are forced: a range next to upstream's own makes every
  Chromium tag a collision risk, and `update_resource_ids/assigner.py` requires ids to be non-decreasing in file
  order unless a jump lands exactly on an id already seen — so an entry of 13000 in the alphabetical
  `chrome/browser/` section makes the *next* entry a backwards jump and
  `//tools/gritsettings:default_resource_ids` fails the build with `Cannot jump to unvisited`.
- `chrome/chrome_repack_locales.gni` — the source pattern and the dep. **Without the source pattern the
  per-locale pak is built and then not folded into `<locale>.pak`**, so every `IDS_REDROB_*` resolves to English
  at runtime while the build stays green.
- `chrome/browser/ui/views/tabs/vertical/BUILD.gn` — the dep that orders grit before the compile.

`tools/gritsettings/translation_expectations.pyl` also lists the grd as untranslated-by-the-console, which is
true: it is translated in-tree from the TSV instead.

## Adding a second language

Add a column to every `l10n/*.tsv` and the language to `TRANSLATIONS` in `gen_strings.py`. A locale with no
translation file falls back to English per-message, so a partial language is not a broken build — but
`gen_strings.py` refuses an empty cell, because an untranslated string should be the English text written out
deliberately rather than a blank nobody noticed.

`l10n/locales.tsv` is the 84 `(pak suffix, grit lang)` pairs taken verbatim from
`chrome/browser/indigo/resources/indigo_strings.grd`, so this grd declares exactly the locale set
`repack_locales` expects. Two rows are not identities and that is upstream's doing: the `en` pak is named
`en-US`, and the `no` pak is named `nb`.

## What is NOT translated

- **Product names**: Redrob, Redrob Code, Google, ChatGPT, Claude, MCP.
- **Sign-in strings still say Google**, because it is a Google account for Chrome sync.
- **Model identifiers** like `redrob/auto`, and `gpt-5.1` in a placeholder — these are values a user types, not
  prose.
- **Hanja and decomposed Jamo** come from system fallback, not from Pretendard, which is why the `.deb` depends
  on `fonts-noto-cjk`. Pretendard covers 11172/11172 Hangul syllables and 0/20992 Han.
